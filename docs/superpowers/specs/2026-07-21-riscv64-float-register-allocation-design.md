# RISC-V64 浮点寄存器分配设计

## 背景

当前 RISC-V64 后端只为 `i1`、`i32` 和指针值分配物理寄存器。`F32` 值始终通过栈槽保存，浮点二元运算通常需要先从栈中加载两个操作数，在 `fa0/fa1` 中计算，再把结果写回栈。循环累加器和浮点 phi 因此会在每次迭代中产生额外的 `flw/fsw`。

RISC-V64 性能测试中的 `h-2-*` 包含 6000 x 6000 的浮点初始化与点积循环。当前 O1 单例运行时间约为 0.8 至 1.2 秒，而且 O1 相比 O0 的改善有限。浮点寄存器分配是这类热点中最直接、最通用的后端改进。

实现应在 PR #30 的矩阵优化合并后开始，或直接基于 `origin/feat/matrix-foundation` 开发。该分支已修改 RISC-V64 整数寄存器分配的调用活跃性处理；在旧 `main` 上独立实现会造成不必要的冲突和重复工作。

## 目标

- 为 RISC-V64 的 `F32` IR 值分配物理浮点寄存器。
- 消除浮点热点循环中 phi、算术中间值和重复使用值的逐迭代栈往返。
- 正确处理基本块边界、phi 边复制和函数调用造成的寄存器破坏。
- 保留现有栈槽作为无法分配、超出分析预算或遇到不支持形状时的正确回退。
- 不改变 x86_64、AArch64 或 IR 优化行为。

## 非目标

- 不实现 RISC-V Vector 扩展或自动向量化。
- 不实现循环融合、数组收缩或浮点重结合。
- 不支持 `F64`；当前 IR 只需要 `F32`。
- 不引入机器 IR、完整 spill 重写或 live-range splitting。
- 不把整数和浮点值放入同一个寄存器类别或干涉图。

## 总体结构

整数分配继续由现有 `Riscv64RegAlloc` 负责。新增独立的 `Riscv64FloatRegAlloc`，放在 `src/codegen/target/riscv64/regalloc/float.rs`。父模块保留 CFG 活跃性、调用活跃性、phi affinity 和热点权重等共享分析；浮点分配器只负责选择 `F32` 候选、着色和记录使用的 callee-saved 浮点寄存器。

`Riscv64IrFuncEmitter` 同时持有整数和浮点分配结果，并提供类型明确的访问接口：

- `assigned_reg(ValueId)` 只返回整数寄存器。
- `assigned_float_reg(ValueId)` 只返回浮点寄存器。
- 浮点加载、结果保存、参数接收、返回和 phi 搬运不得通过整数接口猜测寄存器类别。

这种分离可以避免生成非法的 `mv`、`lw/sw` 或整数 phi copy，同时让整数分配行为保持不变。

## 寄存器类别

浮点分配器不使用 `fa0/fa1`，因为当前指令选择把它们作为固定浮点求值寄存器；也不使用 `ft0`，将其保留为浮点 phi cycle scratch。

- Caller-saved 候选：`ft1-ft11`。
- Callee-saved 候选：`fs0-fs11`。
- 固定求值寄存器：`fa0`、`fa1`。
- phi 环拆解寄存器：`ft0`。

所有类型正确、具有实际使用的 `F32` 参数和指令结果都可以成为候选，包括生命周期完全位于单个基本块内的值。不跨调用的值优先使用 `ft1-ft11`；只有 caller-saved 寄存器不足且收益足以覆盖序言成本时，才为这类值使用 `fs0-fs11`。任何在调用前定义并在调用后仍然活跃的值只能使用 `fs0-fs11` 或回退栈。调用实参可以从已分配寄存器搬到 `fa0-fa7`，参数也可以在入口从 `fa0-fa7` 搬入分配位置，因此二者不因身份本身被排除。

候选按现有循环深度加权的使用次数排序。干涉值必须使用不同寄存器；不干涉的 phi incoming/result 优先使用同一寄存器，以删除边复制。

## ABI 与栈帧

只有实际分配到的 `fs0-fs11` 需要在函数序言保存、尾声恢复。保存区域与整数 callee-saved 区域统一计入函数栈帧大小，但分别维护寄存器列表和偏移。

每个浮点保存槽预留 8 字节，以保持现有栈帧计算简单和稳定；保存与恢复使用 `fsw/flw`，因为编译器只保存 `F32`。整数保存槽继续使用 `sd/ld`。最终保存区域和整个函数栈帧仍按 16 字节对齐。

函数参数处理按 ABI 位置读取 `fa0-fa7` 或调用者栈槽。如果参数获得浮点寄存器，入口直接用 `fmv.s` 或 `flw` 写入目标寄存器；否则保持现有栈槽路径。浮点返回值从分配寄存器或栈槽加载到 `fa0`。

## 指令生成

新增浮点专用辅助接口：

- `load_float_value(value, destination)` 优先从已分配浮点寄存器取得值，否则处理常量或栈槽。
- `store_float_result(value, source)` 优先写入已分配浮点寄存器，否则写回现有栈槽。
- 浮点 `load` 可以直接写入结果寄存器；浮点 `store` 可以直接从已分配寄存器发射 `fsw`。
- 浮点调用返回值从 `fa0` 写入分配位置。
- `I32ToF32`、`F32ToI32`、浮点比较、负号和二元算术使用类型明确的加载与保存路径。

第一版允许浮点算术继续在 `fa0/fa1` 中求值，再以一条 `fmv.s` 写入已分配结果寄存器。这样已经能删除主要的栈流量，同时保持指令选择改动集中。验证收益后，可以单独优化为直接以结果寄存器作为算术 destination；这不是第一版的完成条件。

## Phi 搬运

现有 `PhiLocation::Reg` 只表示整数寄存器。它将拆成明确的整数和浮点位置：

- `IntReg`
- `FloatReg`
- `StackSlot`

浮点寄存器之间使用 `fmv.s`，浮点寄存器与栈槽之间使用 `flw/fsw`。浮点复制环使用保留的 `ft0` 拆解；整数复制环继续使用 `t2`。常量 incoming 按目标类别重新物化。

并行复制超过预算或遇到不支持形状时，snapshot 回退也必须按值类型保存和恢复，不能把已分配浮点值强制通过整数 `a0/a1` 路径搬运。所有 phi copy 完成后，边上的可观察结果应与现有栈实现一致。

## 分析预算与回退

浮点分配复用整数分配已有的块数、值数、候选数、`block x candidate`、活跃性迭代和调用活跃性工作量预算。浮点候选单独计算，不与整数候选争用同一候选上限。

分析不收敛、超过预算或无法证明调用安全时，该函数的相关浮点值保持在栈上。保守回退不得进行不精确的 caller-saved 分配。没有浮点候选的函数应生成与修改前等价且尽量字节稳定的汇编。

## 测试

单元测试覆盖：

- 浮点循环 phi 和跨块值能够获得寄存器。
- 相互干涉的浮点值获得不同寄存器。
- phi affinity 能让不干涉的 incoming/result 共用寄存器。
- 不跨调用的值可以使用 `ft1-ft11`。
- 跨调用活跃的值只能使用 `fs0-fs11` 或回退栈。
- 使用的 `fs*` 在序言和尾声成对保存、恢复。
- 浮点 phi 环使用 `ft0` 正确拆解。
- 超出预算时保持正确的栈路径。

汇编级测试至少包含一个点积循环，确认浮点 accumulator 不再在循环回边上执行逐迭代 `flw/fsw`。还应覆盖浮点参数、浮点返回值、调用结果、cast、比较、load/store 和混合整数/浮点 phi 边。

验证命令包括 `cargo test --locked`、`cargo fmt -- --check` 和针对改动代码的 Clippy。WSL 中运行 RISC-V64 O0/O1 功能测试，再运行完整 `perf-riscv64`。

## 性能验收

- RISC-V64 O0/O1 功能测试无新增失败。
- `h-2-01`、`h-2-02`、`h-2-03` 各运行多次并比较中位数；至少两个用例改善 20%，三者几何平均改善至少 15%。
- 完整性能集无新增超时、崩溃或输出差异。
- 对明显回退的用例检查汇编；若回退来自无收益的 callee-saved 保存成本，则提高分配收益门槛，而不是接受稳定退化。
